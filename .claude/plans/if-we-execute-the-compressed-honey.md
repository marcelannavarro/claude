# Restructure SFCC-249 Contentful TSD into the Prescribed TSD Template — Sizing & Approach

## Context
The Contentful Integration TSD (Confluence `346783750`, titled "…(SFCC-249)", currently **v30**) was authored as a **topic-organised briefing / reference** for the incoming Contentful squad. Zimmermann now has a prescribed **"Technical Solution Document (TSD) Template"** (Confluence `352419841`; local mirror `~/Downloads/Zimmermann-PWA/TSD-Templates/TSD-Template.md`) that TSDs are expected to follow. This plan answers "how big is the change to convert the current doc into that template" and recommends how to approach it.

## Verdict: LARGE — a re-genre / rewrite, not a reformat
The template is a **single-problem decision document**: Problem → Constraints/Assumptions → Options Analysis (A/B/C) → Recommended Option → Technical Implementation → Testing → Risks → Decision Record + Sign-off. The current TSD is a **multi-topic descriptive briefing**: architecture, content-model catalogue, build scope, error handling, handoff, ownership, blockers. Converting is a genre change, driven by three compounding factors:

1. **"One TSD = one problem" conflict (the biggest driver).** The template explicitly rejects multi-topic docs ("if you're writing 'and also…' you need a second TSD"). The current doc spans ~6 topics and ~13 content types. Faithful conversion means either narrowing to one problem and spinning the rest out, or bending the template.
2. **~4–5 template sections are net-new authoring.** The current doc has no equivalent content for them — especially **Section 3 Options Analysis** (it states resolved designs, not alternatives), **Section 6 Testing & Validation** (entirely absent), and the **Section 8 Sign-off**.
3. **~30–40% of current content has no clean template home** and must be dropped, linked, or moved to separate docs (a scoping/content-loss decision, not a copy-paste).
