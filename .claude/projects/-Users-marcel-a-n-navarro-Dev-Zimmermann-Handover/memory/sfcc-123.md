A **working single-product bridge already exists** (`productHero.tsx` + `hotspotPopup.tsx` pass a Contentful `productId` string into `useProduct`) but it's **client-side, in leaf components, built against a MOCK space, plain string fields, no category/multi-product equivalent** — this = current-state "Option C", and SFCC-238 flags it **conflicts with the container/presentational rule and the SSR-first / ≤2s p75 mobile LCP mandate → needs an explicit ruling**. SFCC-238 tasks: map the connector app's field type/payload to the hook key; rule client-side hook vs SSR fetch-and-pass-down; cover category + multi-product refs; close HPC-001 (product name/price ownership).

Verdict recorded: **A is the best-aligned (and only) page-scoping design on record**, matching the SSR-first + dumb-component + cache-key mandates — but it is NOT "the best whole solution": it's only half the design (reference-resolution deferred to SFCC-238), its specific "plain ShortText author-typed" field mechanic may be superseded by the installed connector app's structured refs, the built code is the conflicting client-side C approach (unbuilt migration to A), and it carries no ratification. For a reformatted TSD: present A's page-scoping concept as recommended for P1 (trade-off: raw-ShortText typo risk vs connector-app picker); do NOT present A as the reference-resolution answer — cross-reference SFCC-238; the genuine options tension (SSR-container vs client-side-leaf resolution) is SFCC-238's to decide, so defer not pre-empt.
