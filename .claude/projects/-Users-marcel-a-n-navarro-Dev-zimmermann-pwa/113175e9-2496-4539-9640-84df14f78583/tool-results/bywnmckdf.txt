10. Given a shopper opens the mobile drawer, when the drawer is active, then the hamburger icon is replaced by a close icon on the left. Search and Bag icons remain visible on the right.
11. Given a shopper taps the close icon on mobile, when activated, then the mobile drawer is dismissed and the hamburger icon is restored.

*Category Taxonomy*
12. Given the Navigation component renders, when it reads top-level nav items, then items and their display order are driven by the SFCC category taxonomy configured in Business Manager (SFCC-28) and are not hardcoded in the component.
13. Given a nav item corresponds to an SFCC category, when a shopper clicks it, then they are navigated to the corresponding category PLP.
14. Given Z.IMMERSE is configured as a direct link nav item, when a shopper clicks it, then they are navigated directly to the Z.IMMERSE landing page and no mega menu is triggered.
15. Given the Navigation component fetches top-level categories, when it renders, then it reads from the storefront-specific catalogue assigned to the active storefront, ensuring nav items and their ordering reflect the correct regional configuration.
16. Given a category is set to offline in Business Manager for a specific storefront, when the Navigation component renders on that storefront, then the corresponding nav item does not appear in the headline nav.

Given a shopper is on a category page or any sub-category page within a top-level category, when the Navigation component renders, then the corresponding top-level nav item is displayed in its active state (underlined) to indicate the shopper's current location. - confirm with design{color}

*Scroll Behaviour*
18. Given a shopper scrolls down the page, when the page scrolls, then the Navigation component remains fixed to the top of the viewport and is always visible across all page templates and storefronts.
19. Given a shopper scrolls down the page, when scroll behaviour is triggered, then any animation or visual change to the nav is consistent across all page templates. Note: exact scroll animation is pending design confirmation via SFCC-93 and will be added as an addendum prior to build.

*Accessibility*
20. Given a screen reader user is navigating by landmarks, when they reach the main navigation, then it is wrapped in a nav element with aria-label equal to Main navigation, distinguishing it from any other nav regions on the page.
21. Given a screen reader user navigates the headline nav, when they move through the top-level items, then each item is announced correctly and the number of items is communicated via a list structure.
22. Given a keyboard-only user is navigating the header on desktop or tablet, when they Tab through the headline nav, then each top-level item and icon receives focus in left-to-right order.
23. Given a screen reader user navigates to a top-level item that triggers a mega menu, when the item receives focus and the menu is closed, then the item is announced with aria-haspopup true and aria-expanded false.
24. Given a screen reader user activates a mega menu trigger, when the menu opens, then aria-expanded updates to true and the CLOSE X control is focusable and announced as Close menu.
25. Given a screen reader user navigates to Z.IMMERSE, when the item receives focus, then it is announced as a standard link with no aria-haspopup or aria-expanded attributes.
26. Given a keyboard-only user is on mobile with the drawer closed, when they Tab to the hamburger button, then it is announced as Open navigation menu with aria-expanded false.
27. Given a keyboard-only user opens the mobile drawer, when the drawer is active, then the close icon is announced as Close navigation menu with aria-expanded true.
28. Given a keyboard-only user is interacting with the nav on any device, when they interact with any element, then all interactions are achievable without a mouse.
