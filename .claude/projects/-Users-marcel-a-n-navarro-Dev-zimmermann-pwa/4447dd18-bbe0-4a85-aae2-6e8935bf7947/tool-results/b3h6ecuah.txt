### 5c. Root cause — the PDP is broken server-side (the real blocker)

The `dev-server.log` artifact from both attempts is decisive. **Every** SSR request to
`/product/*` throws:

```
pwa-kit-runtime.httprequest INFO (…) GET /product/8637DS241-3
pwa-kit-runtime.catchAndLog ERROR [object Promise]:
{"stack":"ReferenceError: Cannot access '__WEBPACK_DEFAULT_EXPORT__' before initialization
    at Module.default (…/build/main-server.js:71360:42)
    at …/build/main-server.js:130921:68
    at processTicksAndRejections (node:internal/process/task_queues:104:5)"}
```

19 occurrences in attempt 1; the same in attempt 2. It fires for **valid and invalid SKUs alike**
(`/product/8637DS241`, `/product/8637DS241-3`, `/product/INVALID-SKU-00000`) — which is why even
the *error-state* test fails. Homepage requests are unaffected (the 2 smoke tests pass).

Read: **this is not a sandbox-provisioning gap, not a fixture problem, and not a missing CI secret.**
The PDP route 500s on the server on every request. `ReferenceError: Cannot access
'__WEBPACK_DEFAULT_EXPORT__' before initialization` inside a `loadable()`-split chunk is the
classic signature of a **circular import / TDZ cycle** in the PDP module graph
(`conventions.md` explicitly bans circular imports).

I did not identify the exact cycle — that needs proper root-causing, not guessing. Two things worth
looking at first, offered as hypotheses only:
- Both `pages/product-detail/index.tsx:5` and `components/ui-kits/atoms/zimmPageToolbar/index.tsx:3`
  import from the `@salesforce/retail-react-app/app/components/shared/ui` **barrel**, while
  `components/breadcrumb/index.tsx:3` imports from `@chakra-ui/react` directly. That barrel is a
  known hazard in this repo.
- `components/pdpProductInfo/index.tsx:4` imports runtime constants from
  `'app/theme/components/pdpProductInfo'` via the `app/` path alias, and that same module is pulled
  in by `theme/components/index.ts` → `theme/index.ts` → `_app-config`.

The `Deploy Preview` job succeeded, so the MRT preview URL in the PR is worth a manual check to
confirm the same failure outside the CI runner.
