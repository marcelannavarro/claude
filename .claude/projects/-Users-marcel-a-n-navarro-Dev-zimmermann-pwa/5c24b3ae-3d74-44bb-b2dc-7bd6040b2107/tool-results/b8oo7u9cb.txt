 Three layers, three purposes. **Do not duplicate coverage across layers** — pick the cheapest layer that proves the behaviour.
 
+**This is not license to skip a component's own test file because its behaviour happens to be
+covered transitively elsewhere.** A component with real logic (branching, prop→JSX mapping
+decisions, event wiring) gets its own `index.test.ts`/`index.test.tsx`, even when the state it
+renders is owned by a hook that already has its own test, or a parent's assembly-level
+Storybook `play` already exercises the rendered result. Resolve the duplication concern by
+**scoping what that file asserts** — mock the hook/child component whose internals are proven
+elsewhere, and test only this component's own contract (given a state, does it render the
+right branch; given a DOM event, does it call the right handler) — not by leaving the
+component with no test of its own. Relying on a *different* component's story to prove *this*
+component's contract means the coverage isn't discoverable from the component's own folder,
+and can silently vanish if that unrelated file changes. See
+`overrides/app/components/ui-kits/organisms/zimmSubscribeSection/index.test.tsx` for the
+resulting pattern (mocks `useSubscribeSection` and `ZimmSubscribeModal`, tests only its own
+render-branch/event-wiring contract). A component with no branching or decision logic at all
+(pure prop interpolation, e.g. `BottomBar`) still doesn't need its own suite — the exemption
+below for single-parent internal components still applies there.
