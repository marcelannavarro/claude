630-## 5.0 Verification standard (added 2026-09-19, applies to every remaining step, 3.6 onward)
631-
632-Six real, currently-shipped defects were found in commits already scored PASS on Design fidelity,
633-by a from-scratch re-audit that rendered the real components live instead of reading source and
634-Figma side by side. Every one of the six traces back to one of the gaps below. These are now
635-mandatory for every remaining step's Design-fidelity check — not optional rigor, a gate. When
636-dispatching Tester/Scorer for 3.6 onward, brief them with this section explicitly: they start
637-each run with no memory of today, so the standard has to be restated, not assumed carried over.
638-
639-1. **A rendered-output claim needs a live measurement citation, not a source read.** "The recipe
640-   sets `fontWeight: 500`" is not the same claim as "the rendered text measures `font-weight: 500`
641-   in a real browser" — the first can be true while the second is false. Every Design-fidelity
642-   PASS from here on cites an actual measured value (computed style, bounding box, or a real
643-   screenshot) against the actual Figma-sourced value, for every property being signed off, not
644-   just the ones that seem most at-risk.
645-2. **A wrapper's correct style does not prove a nested element inherits it.** Two of the six
646-   defects were exactly this shape: `textStyle`/`fontWeight` correctly set on a container, silently
647-   lost before reaching the actual visible text, because the nested element was either a Chakra
648-   component with its own competing theme registration (`Heading`, and by extension `Button`/
649-   `IconButton`/`Modal`/anything imported from `@chakra-ui/react` un-wrapped in a plain `chakra.*`
650-   factory) or a literal HTML tag with its own default rendering (`<b>`, via a base SFCC
651-   component). Whenever a style is applied above a boundary like that, verify the leaf text node's
652-   own computed style directly — inheritance is not something to assume across it.
653-3. **A previously-recorded "confirmed correct" is not permanent proof.** This exact document's own
654-   audit trail (`figma-reference/discrepancies.md`) both found real bugs *and*, twice, had to
655-   retract its own "confirmed" claims once they were checked against a real render instead of
656-   restated from a prior pass. Re-verify against a live render before citing an earlier pass as
657-   settled, especially for anything touching the same file again.
658-4. **Storybook `play` functions auto-run on load.** A live check against a story with a `play`
659-   function is measuring the *post-play* state by the time any normal wait resolves, not the
660-   initial seed — sample within ~100ms of mount if the true initial state matters, and never treat
661-   a play function's own scripted end-state as a seeding bug.
662-5. **Read the real, current JSX before asserting how two elements relate.** More than one
663-   mis-scoped finding this pass came from reasoning about layout from a written description
664-   instead of the actual current source — siblings vs. nested, same container vs. different, is
665-   checkable in seconds and shouldn't be inferred.
666-6. **A fix for one interaction can silently break a different one.** The focus-ring fix's first
667-   attempt passed its own new test and broke backdrop-click-to-close, undetected until the full
668-   existing suite was re-run. Any interaction/focus/event-handling change re-runs the component's
669-   *entire* existing test suite, not just the new assertion, before being called done.
670-7. **Mutation-test every new test, and disclose when jsdom genuinely can't.** Revert the fix,
671-   confirm the new test fails with the real wrong value; restore, confirm it passes. If a property
672-   (native `:focus-visible` matching is the known example so far) can't be made mutation-sensitive
673-   under jsdom, say so directly in the test's own comment rather than claim proof the test doesn't
674-   actually provide — the real proof in that case is the live-browser verification, cited as such.
675-8. **No AI attribution, no third-person references to any person, in any commit message.**
676-   Objective and technical only — what changed and why, not who caught it or confirmed it. Two
677-   rounds of whole-branch correction this pass were both this exact category.
678-9. **A green Vitest suite does not prove a `.stories.tsx` file actually renders (added 2026-09-20,
679-   after step 4.4 shipped four crashing stories through an entire round-0 build, its Tester's Full
680-   loop, and its own Orchestrator, all green).** `ZimmCartItemActions` called `ZimmLink`, which
