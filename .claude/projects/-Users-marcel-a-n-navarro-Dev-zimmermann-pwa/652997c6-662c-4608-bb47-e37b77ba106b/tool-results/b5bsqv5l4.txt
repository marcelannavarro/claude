212	## Integration Map
213	
214	All order-creation, fulfilment write, and CRM sync traffic from SFCC routes through MuleSoft as the middleware layer — SFCC does not call NewStore, AP21, Omneo, or Narvar directly. In addition, the PWA's MRT Node layer calls MuleSoft directly for read operations (order history, order details, boutique / BOPIS stock check, real-time stock availability, GiveX balance check) — SFCC is not in those read paths. A handful of services are also called **browser-direct from the PWA** and another set are **SFCC cartridge integrations** invoked server-side. The `Boundary` column makes this explicit so you know where to look when an integration breaks.
215	
216	**Boundary key:**
217	
218	- **PWA-direct** — called from the browser directly. Vendor key (if any) is publishable/public and safe in the bundle.
219	- **MRT-mediated** — called from the PWA's Node layer via `/mobify/proxy/` or a server-only endpoint. API credentials held as MRT environment variables; never reach the browser bundle. Includes direct PWA → MuleSoft calls via MRT proxy.
220	- **SFCC (OOTB)** — Salesforce-bundled integration; no custom cartridge.
221	- **SFCC (cartridge)** — vendor-supplied or custom server-side cartridge running inside SFCC.
222	- **SFCC → MuleSoft** — SFCC calls MuleSoft, which fans out to the downstream system.
223	- **Browser handoff** — PWA hands the user off to a third party's hosted experience.
224	- **Out-of-band** — no runtime call from PWA or SFCC; the integration delivers data via a separate channel.
