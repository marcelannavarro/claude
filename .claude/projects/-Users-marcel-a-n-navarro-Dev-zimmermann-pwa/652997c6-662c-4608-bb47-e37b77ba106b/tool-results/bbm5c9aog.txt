title: feat(ci): add version-guard to block downgrades on tag-promoted deploys
branch: feature/version-guard
----------------------------------------------------------------------
# Description

Adds **downgrade protection** to the manually-promoted, tag-based deploy tiers
(`test` / `uat` / `staging` / `prod`). Before a deploy, the guard reads the
environment's last recorded deployed tag and **blocks** a push whose tag is *older*
than what's live; after a successful push it **records** the deployed tag.

Why the recording step: on the GitHub **Team** plan, a deploy's auto-created
Deployment records the *trigger* ref (the default branch), not the deployed tag — so
we record the tag ourselves (an explicit GitHub Deployment) and read it back to compare.

`dev` and `sit` are the continuous auto tiers (no human-picked tag — `dev` deploys
`develop`'s latest, `sit` deploys the gate's commit SHA), so a tag-downgrade guard does
not apply and they are intentionally excluded.

# Known gaps and follow-ups

A `/code-quality` audit against `develop` ran before this PR. Nine findings were triaged as
follow-ups rather than fixed here — none changes behaviour, and each would either edit a
copy-first port or refactor tests late in a gated PR:

- **Types.** Both ports alias `SfccProduct`/`Variant`/`Category`/`PriceData` to `any`. The
  in-file justification has been corrected: `@salesforce/retail-react-app` shipping no types is
  true but beside the point — these shapes are `commerce-sdk-isomorphic`'s and it does export
  `ShopperProductsTypes`. Substituting also clears 3 of the 15 lint warnings, which moves a
  baseline this branch holds as an invariant across all 8 commits — hence not bundled here. The
  same follow-up covers `SfccVariationValue.image` (declared a Product, read as an `Image`) and
  `name: string` where upstream is `name?: string`.
- **`renderHeader` has no test.** Both call sites pass byte-identical prop objects today with
  nothing pinning that, and the default-vs-supplied branch is untested. A test needs the shared
  `renderWithProviders` helper `testing.md` calls for and that doesn't exist yet — that helper is
  the real unit of work.
- **Selectors.** The seven new components carry `data-testid`; `testing.md` wants role/text first
  and reserves test IDs for elements with no semantics. Zero of the ten existing Zimmermann
  `ui-kits` components use one, so this is a divergence worth correcting — as a test refactor with
  its own review, not late here. The two molecule wrappers legitimately qualify and would stay.
- **Assertion consistency.** Collapse behaviour is asserted three ways across six suites;
  standardise on `toBeEmptyDOMElement()`.
- **The seven registration pins catch an unregistration only** — a recipe emptied to `{}` still
  passes. Four of the seven pin no resolved value anywhere, which matters more now type lives in
  the recipes. Documented in-file; closing it means asserting a resolved value per recipe.
- **`staticProductHeader.tsx:58,60`** carries bare Chakra keys lifted verbatim from base
  `product-view`. `minWidth={64}` is the one that matters — `sizes` is not a registered scale
  here, so a bare key can misresolve rather than just read oddly.
- **`app/constants` is imported by base path in both ports** (base-verbatim). No behavioural
  impact — the override is a pure superset re-export — but a constant's *value* changing would
  split base consumers from these two files.
- **The shipped ProductView/PDP path has no coverage in this repo.** Base ships `index.test.js`
  for both (39 and 24 cases); `vitest.config.ts` scopes collection to `overrides/**`, so they
  never run here. Not a CI regression — the override now shadows the implementation those suites
  were written against. Base's suites are a ready-made porting source.

Owner-side, not ours: the cap-height/leading-trim spacing question and a named 28px spacing step
(designer — `--zimm-scale-700` is raw px for a spacing alias, against the Units rule);
`overrideStyling.md`'s `isFromExtends` rationale is wrong in a way that *understates* the rule,
and its "known instance" cites two files that exist on no branch (governance); no ESLint
`import/*` rules, so the highest-value override rule is human-review-only (Integration).
