261:## Customer Data Migration (DMU-004, updated 2026-05-29)
263:Only **email + Omneo customer ID** are migrated into SFCC at go-live. All other customer profile data — name, phone, addresses, communication preferences — is sourced **live from Omneo at login** via MuleSoft. Implication: My Account profile pages cannot rely on SFCC for the full customer record; an Omneo round-trip is required post-authentication. Graceful degradation for Omneo outages becomes load-bearing on account screens. Asset/CDN migration (DMU-010) is **de-scoped** — images stay in Contentful, no asset 301s.
267:Multiple upstream integrations (SFCC, MuleSoft/Omneo, Global-e, Narvar, Contentful, Didomi, Inside Chat) mean a failure or attack targeting one service must not cascade. A PWA-relevant mitigation can be done in the SSR layer.
269:The SSR layer in `overrides/app/ssr.js` uses **Node's native `fetch`**, which is backed by `undici`. Undici's `dispatcher` option (the per-call `dispatcher` option on individual `fetch()` invocations) allows each upstream origin to be given its own connection pool with an independent cap. This prevents a slow or flooded integration (e.g. checkout APIs) from exhausting connections for unrelated origins (e.g. Contentful, JWKS).
