**Rule:** when drafting a message for the user to send to a colleague, only include what that
colleague's own role/discipline needs to act — strip anything that's really "how the sausage
got made" on the research/delivery side, even if it's accurate and was hard-won.

**Why:** corrected twice in the same drafting task (2026-08-11, the Booxi/Book-a-Fitting
calendar question from a designer, Kiera Rikard-Bell, to the user). First pass used a "good
news / bad news" framing — rejected as unnecessary editorializing. Second pass still named
Tim Lavelle, a specific PM/BA Teams thread, and "we still need a session with Booxi on
implementation approach" — rejected as oversharing, because Kiera is a designer, not a FED
(front-end developer), and none of that internal delivery-process detail is something she
needs in order to answer her own question. The user's framing: keep the reply "mainly
concerned with the design" for a design audience — i.e. filter by *what changes for the
recipient's own work*, not by what's true or interesting.

**How to apply:** before sending a drafted reply, ask "does the recipient's role change what
they'd do with this fact?" A designer needs to know a vendor's widget would constrain her
visual freedom — she doesn't need to know which internal Teams channel confirmed scope, who
said it, or that a follow-up session hasn't happened yet. Reserve those specifics for messages
to people in the same discipline as the underlying research (PM/delivery/dev), or for the
user's own reference — not for cross-discipline replies. When in doubt, cut toward the
shorter, role-scoped version and let the user ask for more detail if they want it restored.
