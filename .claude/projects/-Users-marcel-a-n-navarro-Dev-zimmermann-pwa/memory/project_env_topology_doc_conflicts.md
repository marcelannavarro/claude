Verified 2026-08-05 against the real `.github/workflows/` + `gh` API. Several docs disagree with each other and with the code. Flag these (doc-integrity rule) before wiring release/promotion tooling; do not silently pick one.

1. **Test tier existence — CORRECTED 2026-08-10: `.docs/architecture.md` is also stale, not an exception.** Confluence "Environment Topology & Promotion Path" (page 304840708, still v4 as of 2026-08-10) describes a 6-tier model **with no Test tier** (LOCAL→DEV→SIT→STAGE→UAT→PROD). This entry originally also listed `.docs/architecture.md` as correctly including Test — **that was wrong**; a fresh full read of `.docs/architecture.md`'s own "Environments" table (2026-08-10) shows the identical 6-row Local/Dev/SIT/UAT/Stage/Prod table with **no Test row**, and `.docs/temp/tsd-architecture.md §14.1` carries the exact same 6-row table verbatim (same staleness, shared/copied content). So `.docs/architecture.md` and `tsd-architecture.md` are stale on this point **the same way** the Confluence topology page is — not a source that contradicts it. What *does* correctly include Test: 05.6 Environment Details (285540356), the tag proposal (335216656), SFCC-254, `.claude/rules/tagging.md` (repo governance file, correct), and the actual `deploy-test.yml` + `test` GitHub Environment + `deploy-then-gate` bundle-size job (live).

2. **Promotion order (Stage vs UAT).** Topology page 304840708 orders **STAGE → UAT** (Stage = convergence, then UAT business acceptance). `.docs/architecture.md` and the tag proposal order **UAT → STAGE → PROD**. Genuinely different sequencing — needs a team decision; affects promotion tooling.

3. **SIT trigger model.** Topology page + 05.6 say SIT **auto-deploys on every `develop` push** after sit-gate. Reality: `deploy-sit.yml` triggers on `workflow_run` of **"SIT Gate" (digital-sit.yml) completing on `release/**`** — SIT is release-branch-driven, not develop-driven. `.docs/memory/projectState.md` has this right; the Confluence pages don't. (This is the tag proposal's still-open Question 3.)

4. **GitHub Environment names.** Topology page's secret-scope table names `pre-prod` and `production`; the **actual** environments are `staging` and `prod`. `deploy-stg.yml` binds `environment: staging` (filename says `stg`); `deploy-prod.yml` binds `prod` but the MRT push target is `production`. Version-guard/promotion tooling must key off the real names (`dev/test/sit/uat/staging/prod`) — the `stg`≠`staging` mismatch already caused a bug once (commit 12bf91b).

5. **CI/CD architecture stale.** "PWA CI/CD Pipeline" (305561601) and "7.1c Checklist" (305430530) describe `deploy-sit` as a **job inside `digital-sit.yml`** and list the `sit` environment + MRT secrets as not-yet-created. Reality: separate `deploy-*.yml` workflows, and all six environments exist. 7.1c/305561601 need a refresh.

6. **`mobify.config.js` referenced but absent.** frozenFiles.md (Tier 1), `protected-file-guard.yml`/`qa.yml` path filters, `architecture.md`, and 7.1c all reference `mobify.config.js` — the file **does not exist**. `package.json` has no `mobify` key (uses `ccExtensibility`). MRT config actually lives in `config/default.js` `ssrParameters`. Verify where the MRT project slug for `pwa-kit-dev push` actually resolves from.

7. **Bundle-size budget mismatch (found 2026-08-06 during Step 7 V&V).** Topology 304840708's DEV-gate lists `vendor.js < 250 kB` + a `main.css < 50 kB` check. Reality: `package.json` `bundlesize` = `main.js ≤ 180 kB`, `vendor.js ≤ 550 kB`, **no main.css check**. Material: the actual vendor.js build is ~515 kB — passes the real 550 budget, would FAIL the doc's 250. Doc budget is less than half the real one.

8. **architecture.md (repo doc) also carries the stale naming (found 2026-08-06).** `.docs/architecture.md:108` says MRT targets in `mobify.config.js` map `dev|sit|uat|stage|production` — uses `stage`/`production` (topology naming), not the real `staging`/`prod` env names, AND references the absent `mobify.config.js` (conflict #6). So D's reconciliation is NOT Confluence-only — a repo doc is stale too.
9. **Confluence ALSO repeats the `mobify.config.js` myth (found 2026-08-10, during SFCC-237 research).** 05.6 Environment Details (285540356)'s "SIT — Operational Details → Config" section: "MRT push credentials (`MRT_USER`, `MRT_API_KEY`)... scoped to the project slug in `mobify.config.js`." Root-caused during SFCC-237 work: `@salesforce/pwa-kit-dev@3.18.0`'s `getConfig()` (via `cosmiconfig`) never searches for a root `mobify.config.js` at all in this version — it resolves `config/{target}.js` → `config/local.js` → `config/default.js` → `package.json`'s `mobify` key, and the project slug actually comes from `package.json`'s `"name"` field. So conflict #6 isn't repo-docs-only either — it's now confirmed on Confluence too. Full detail in [[project_sfcc237_mrt_topology_spike]].
