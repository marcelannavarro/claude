## Living Memory — what belongs where

`.docs/memory/` is the project's persistent memory. Keep it current — update the relevant file whenever a session produces new information that belongs there.

**`.claude/session-notes.md` is different: a lightweight, Claude-writable, gitignored, per-developer staging area** (same pattern as `userProfile.md` below, but for tasks rather than profile info) for short-lived carryover items (e.g. "still need to do X next session") that haven't been promoted to `.docs/memory/` yet. It's **not** shared via git — each developer's notes stay local, so they never conflict or overwrite a teammate's. Unlike the files below, Claude may write to it directly. Use it for quick pending-item tracking; move anything durable and team-relevant into the right `.docs/memory/` file once it's confirmed, and clear the note.

| File | What belongs there | When to update |
|---|---|---|
| `architecture.md` | Stack decisions, overrides pattern, key paths, structural choices | A new integration is added, a structural decision is made, or a key path changes |
| `projectState.md` | Phase, integration statuses (mock/live/not started), what's done and pending, unresolved dependencies | Any integration goes live, a phase changes, a feature is completed, or a dependency is resolved |
| `feedback.md` | What worked, what failed, patterns to avoid or repeat | After discovering a gotcha, a failed approach, or a validated pattern |
| `references.md` | Service URLs, API keys, credentials, logins, dashboards | A new credential or service URL is introduced (system roles live in `architecture.md`) |
| `userProfile.md` | User's role, expertise, working style, preferences | User shares a preference or working-style detail that should persist |

- **Conciseness.** Keep all `.md` instructions concise.
